```
시나리오 1-A: 파일 드래그 앤 드롭
  1. 사용자가 파일을 드래그
  2. 드롭존 색상 변경 (시각 피드백)
  3. 파일 놓으면 검증
     - 형식 확인 (.mp4, .avi, .mov)
     - 크기 확인 (≤ 500MB)
  4. 통과 → 파일 정보 박스 표시
     - 파일명
     - 크기 (자동 단위 변환)
     - "✕" 제거 버튼
  5. [분석 시작하기] 버튼 활성화

시나리오 1-B: 클릭 선택
  1. 드롭존 클릭
  2. OS 파일 탐색기 열림
  3. 영상 파일 선택
  4. 시나리오 1-A의 4~5단계와 동일

시나리오 1-C: 잘못된 파일
  1. 다른 형식 (예: .txt) 또는 큰 파일
  2. alert 메시지 표시
  3. 파일 정보 박스 표시되지 않음

시나리오 1-D: 파일 제거
  1. 파일 정보 박스의 "✕" 클릭
  2. 파일 정보 박스 숨김
  3. 드롭존 다시 표시
  4. [분석 시작하기] 비활성화
```


### 3. 결과 보고서 페이지 (`/result/<job_id>`)

**파일**: `webapp/templates/result.html`

#### 표시 순서 (위에서 아래로)

```
1. 종합 판정 배너 (항상 표시)
   - 정상/일부 주의/전문의 상담 권고/재검사 필요
   - 색상으로 직관적 표시

2. 모드 토글 (항상 표시)
   - [👁️ 일반인용] [🔬 전문가용]
   - 기본: 일반인용

3. AI 신뢰도 박스 (일반인용만)
   - 모델별 검증 결과
   - 펼치기/접기 토글

4. 분석 신뢰도 카드
   - 종합 점수 (0~100)
   - 발견된 품질 이슈

5. 영상 품질 정보 (조건부)
   - B/C 등급, 큰 변환 적용, 심각한 이슈 시에만
   - S등급은 표시 안 함

6. 운동성 분석
   - 도넛 차트
   - 막대 그래프 3종
   - WHO 기준 검토

7. CASA 키네마틱
   - 속도 지표 3종 (VCL/VSL/VAP)
   - 운동 패턴 지표 3종 (STR/LIN/WOB)

8. 형태 분석
   - 분석 정자 수, 정상 형태율
   - 부위별 이상 비율 4종

9. 종합 판정 근거 (일반인용만)
   - 운동성/형태/신뢰도 항목별 영향도

10. 면책 박스
    - "의학적 진단 아님" 명시

11. 액션 버튼
    - [새 분석] [인쇄]
```

#### 모드 토글 동작

```javascript
// result.js

  body.classList.toggle('mode-simple', 'mode-expert')
  localStorage.setItem('aicasa-mode', 모드)

.mode-simple .for-expert { display: none }
```

## ⚙️ 시스템 내부 처리 시나리오

### Step-by-Step 분석 흐름

```
[1. 영상 업로드]
   POST /api/analyze
   → FormData (video file)
   → tmp_uploads/{timestamp}_{filename} 저장
   → JOBS[job_id] 생성
   → 백그라운드 스레드 시작
   → 응답: {job_id}

[2. Step 0 — 품질 평가]
   src/quality.py
   → cv2.VideoCapture로 메타데이터 추출
   → 하드 룰 검사 (duration < 5초 등)
       ↓ 실패
       JOBS[job_id]['status'] = 'rejected'
       반환 (분석 중단)
       ↓ 통과
   → 6차원 점수 계산
   → 가중 평균 → 종합 점수 + 등급

[3. Step 1 — 스마트 정규화]
   src/normalizer.py
   → get_normalization_type(metadata)
       'none' → 변환 스킵, 즉시 다음 단계
       'trim' → fast_trim() 호출
                · 처음 180초만 사용
                · CLAHE 대비 향상
                · 약 5~15초
       'full' → normalize() 호출
                · 해상도/FPS 변환
                · 그레이스케일 + CLAHE
                · 약 30~120초

[4. Step 2~6 — 기존 파이프라인]
   src/pipeline.py:SpermAnalysisPipeline.analyze()
   
   2. SpermDetector (YOLO11) — 정자 탐지
      → 프레임마다 정자 위치
      → 전체 정자 수 N 추정
   
   3. SpermTracker (ByteTrack) — 추적
      → 정자별 이동 경로
      → CASA 키네마틱 계산
        VCL, VSL, VAP, LIN, STR, WOB, ALH
   
   4. MotilityAnalyzer (Ridge+RF) — 운동성
      → 11개 특징 추출
      → 회귀 모델 → 전진/비전진/비운동 % 예측
   
   5. MorphologyAnalyzer (EfficientNet-B3) — 형태
      → 정자 크롭 추출
      → 4부위 분류 (head, acrosome, vacuole, tail)
      → 정상 형태율 계산
   
   6. interpreter.py — WHO 해석
      → 운동성 / 키네마틱 / 형태 각각 해석
      → 신뢰도 점수
      → 종합 판정

[5. 결과 저장]
   JOBS[job_id]['result'] = result_dict
   JOBS[job_id]['status'] = 'done'
   JOBS[job_id]['progress'] = 100

[6. 사용자 자동 이동]
   progress.js 폴링이 status='done' 감지
   → window.location = /result/{job_id}
```

### 폴링 메커니즘

```
[프론트엔드 (progress.js)]
1.5초마다 fetch('/api/status/{job_id}')
  ↓
[백엔드 (routes.py:api_status)]
JOBS[job_id]에서 현재 상태 읽기
JSON 응답
  ↓
[프론트엔드]
status에 따라 동작:
  - running: UI 갱신
  - done: 결과 페이지 이동
  - rejected: 거부 페이지 이동
  - error: 에러 박스 표시
```

### 메모리 관리

```
JOBS 딕셔너리:
  - 메모리 기반 (서버 재시작 시 초기화)
  - 작업 ID마다 1개 항목
  - 결과 + 메타데이터 + 진행 상태 저장

tmp_uploads/ 폴더:
  - 업로드된 원본 영상
  - 정규화된 변환 영상 (_normalized.mp4)
  - 시간 경과해도 자동 정리 안 됨 (수동 필요)

권장 운영 정책:
  - 매일 또는 매주 tmp_uploads/ 정리
  - 서버 재시작으로 JOBS 초기화
  - 장기 운영 시 Redis 도입 검토
```

## 🔄 상태 전이 다이어그램

```
[작업 상태 변화]

pending (생성 직후)
   │
   ▼
running (분석 시작)
   │
   ├─ done      → 결과 페이지
   ├─ rejected  → 거부 페이지
   └─ error     → 에러 박스
```

```
[프론트엔드 화면 전이]

메인 페이지 (/)
   │ POST /api/analyze
   ▼
분석 진행 (/analyzing/{id})
   │ 1.5초마다 polling
   │
   ├─ status='done'     → 결과 (/result/{id})
   ├─ status='rejected' → 거부 (/rejected/{id})
   └─ status='error'    → 에러 박스 (현재 페이지에서)
```
