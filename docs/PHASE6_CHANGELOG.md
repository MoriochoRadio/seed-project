# Phase 6 변경사항 — 영상 품질 평가 + 스마트 정규화

> 다양한 입력 영상을 분석 가능하게 만든 핵심 업데이트

---

## 🎯 Phase 6의 목적

```
기존 문제:
  - VISEM 표준 영상(640×480, 50fps)에만 최적화
  - 다른 사양의 영상은 품질 보장 불가
  - 사용자가 영상 사양을 직접 맞춰야 함

해결 방향:
  - 어떤 영상이든 자동으로 품질 평가
  - 본질적으로 분석 불가능한 영상은 거부
  - 가능한 영상은 시스템에 맞게 자동 변환
  - 변환 시간을 최소화 (스마트 분기)
```

---

## 🆕 새로 추가된 기능

### 1. 영상 품질 자동 평가 (`src/quality.py`)

**6차원 점수 시스템**:

| 평가 항목 | 가중치 | 측정 방법 |
|---|---|---|
| 해상도 | 20% | 640×480과의 비교 |
| 프레임률 | 15% | 50fps 기준 |
| 길이 | 5% | 정규화로 해결 가능 |
| 안정성 | 20% | 프레임 간 차이 분석 |
| 밝기 | 15% | 평균 픽셀값 |
| 선명도 | 25% | 라플라시안 분산 |

**5단계 등급**:

```
S (90~100): VISEM 표준 영상 - 변환 없이 분석
A (75~89):  우수한 영상 - 가벼운 변환 후 분석
B (60~74):  분석 가능한 영상 - 변환 후 분석
C (45~59):  도전적인 영상 - 신뢰도 주의
F (0~44):   분석 거부
```

**하드 룰 (등급 무관 강제 거부)**:

```python
- 영상 길이 < 5초
- 해상도 < 320×240
- 프레임률 < 10 fps
- 프레임 수 < 30
```

### 2. 스마트 정규화 (`src/normalizer.py`)

**3-tier 분기 전략**:

```
none — 변환 불필요
  · VISEM 표준 영상 (해상도/FPS 동일)
  · 즉시 분석 진행

trim — 빠른 컷팅 (5~15초)
  · 해상도/FPS는 표준이지만 길이만 김
  · 처음 MAX_DURATION(180초)만 사용
  · CLAHE 대비 향상 적용 (정자 가시성 ↑)
  · 원본 코덱 유지

full — 풀 정규화 (30~120초)
  · 해상도 또는 FPS가 표준과 다름
  · 640×480, 50fps로 완전 변환
  · 그레이스케일 + CLAHE
```

**진행률 콜백**:

```python
# 정규화 중 실시간 UI 갱신
"영상 정규화 중 (45% — 670/1500 프레임)"
```

### 3. 거부 안내 페이지 (`webapp/templates/rejected.html`)

```
F등급 영상에 대한 친절한 안내:
  - 발견된 문제점 명확히 표시
  - 영상 사양 정보
  - 6항목 권장 촬영 사양
  - "다른 영상 업로드" 버튼

자동 이동:
  분석 진행 페이지에서 status='rejected' 감지 시
  → /rejected/{job_id}로 자동 리다이렉트
```

### 4. 결과 페이지 — 영상 품질 정보 (`webapp/templates/result.html`)

**조건부 표시 로직**:

```python
표시 조건 (셋 중 하나라도 해당):
  1. 등급이 B 이하
  2. 풀 정규화가 적용됨 (해상도/FPS 변환)
  3. 심각한 본질적 이슈 존재

→ S등급 영상은 표시되지 않음 (깔끔)
→ 변환이 필요했던 영상만 사용자에게 알림
```

## ⚙️ 기술적 결정 사항

### 왜 길이 가중치를 5%로 낮췄나?

```
이유:
  - 길이는 정규화로 해결 가능 (자르면 됨)
  - 해상도/FPS와 달리 본질적 한계 아님
  - 임상 표준은 30초~수분이지만 정확한 기준 없음

대신 하드 룰로 보완:
  - duration < 5초 → 무조건 거부
  - 본질적 한계만 강제 거부
  - 그 외는 정규화로 처리
```

### 왜 fast_trim에 CLAHE를 적용했나?

```
실험 결과:
  fast_trim (CLAHE 없음): 선명도 45점
  fast_trim (CLAHE 있음): 선명도 85점
  full normalize:        선명도 85점

→ CLAHE 추가만으로 풀 정규화와 비슷한 품질
→ 시간은 1/10 (5초 vs 50초)
→ 가성비 최고
```

### 왜 표시 조건이 까다로운가?

```
사용자 경험 우선:
  - S등급 영상에 "변환됨" 표시 → 혼란
  - 작은 변환(CLAHE만)도 강조 → 과한 정보
  - 정작 큰 변환 시에만 알리는 게 명확

표시 조건:
  1. B/C 등급 → 사용자가 결과 신뢰도 판단 필요
  2. 해상도/FPS 변환 → "큰 변환" 명시
  3. 심각한 이슈 → 분석 한계 안내
  
  나머지 모두 → 표시 안 함 (깔끔한 UI)
```
