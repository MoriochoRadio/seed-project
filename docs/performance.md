# 성능 분석 상세 보고서

## 1. 탐지 모델 성능 (YOLO11)

### 학습 설정
- 베이스 모델: yolo11m.pt (YOLO11 medium)
- 학습 데이터: VISEM-Tracking 16명 (train) / 4명 (val)
- 입력 해상도: 640×480
- 배치 크기: 16
- GPU: RTX 3080 Ti (16GB VRAM)

### 모델 버전별 성능

| 버전 | sperm mAP50 | 특이사항 |
|---|---|---|
| v1 (기본) | 0.573 | 기본 학습 설정 |
| **v2 (최종)** | **0.677** | 클래스 가중치 조정 ✅ |
| v3 (오버샘플링) | 0.653 | cluster 오버샘플링 시도 |

### 클래스별 탐지 성능 (v2 기준)

| 클래스 | mAP50 | 비고 |
|---|---|---|
| sperm (0) | 0.677 | 핵심 탐지 대상 |
| cluster (1) | ~0.0 | 탐지 포기 (데이터 극도 불균형) |
| small/pinhead (2) | 0.45 | 부분적 탐지 |

### 논문 비교

| 방법 | mAP50 | 데이터셋 |
|---|---|---|

| **본 시스템 YOLO11** | **0.677** | VISEM-Tracking |

> cluster 탐지는 공식 논문에서도 낮은 성능을 보임.

## 2. 운동성 회귀 모델 성능

### 입력 특징 (11개)

| 특징명 | 설명 |
|---|---|
| speed_mean | 프레임당 평균 이동 속도 (px/frame) |
| speed_median | 속도 중앙값 |
| speed_75 | 속도 75th percentile |
| speed_90 | 속도 90th percentile |
| lin_mean | 직진성 평균 (VSL/VCL) |
| lin_75 | 직진성 75th percentile |
| straight_mean | 평균 직선 이동 거리 |
| ratio_fast | 빠른 정자 비율 (> 1.5 px/frame) |
| ratio_medium | 중속 정자 비율 (0.5~1.5 px/frame) |
| ratio_slow | 느린 정자 비율 (< 0.5 px/frame) |
| n_tracks | 추적된 정자 수 |

## 5. v2 개선 시도 및 교훈

### 5-1. MSD (Mean Squared Displacement) 특징 추가

- **방법**: 기존 11개 + MSD 기반 9개 = 20개 특징
- **결과**: 7.01%p (기존 6.93%p 대비 개선 없음)
- **원인**: 기존 속도/직진성 특징과 중복 정보
  - speed_mean, lin_mean 등이 이미 MSD의 정보를 담고 있음
- **교훈**: motilitAI의 MSD는 단순 요약 통계가 아닌 Bag-of-Words 히스토그램 방식으로 집계됨. 동일 방식이 아니면 효과 없음

### 5-2. Isotonic Regression 보정 레이어

- **방법**: LOO 예측값 → IsotonicRegression으로 편향 보정
- **LOO CV 결과**: 6.1%p (개선처럼 보임)
- **실제 검증 결과**: 8.1%p (오히려 나빠짐)
- **원인**: 데이터 누출 (Data Leakage)
  - VISEM-Tracking 20명이 VISEM 85명에 포함되어 있음
  - 보정 레이어 학습 시 검증 데이터를 이미 "본" 상태
  - LOO CV가 과적합된 것처럼 보인 것
- **교훈**: 보정 레이어는 완전히 독립된 새 데이터로만 검증 가능

### 5-3. 참가자 임상 데이터 추가 (나이, BMI 등)

- **결론**: 시도 전에 논문 확인
- **참조**: Hicks et al. (2019) — VISEM 데이터로 실험한 결과, 참가자 데이터(나이, BMI, 금욕 기간) 추가가 성능 개선에 도움이 되지 않음을 확인
- **교훈**: 영상 기반 특징이 임상 데이터보다 더 강한 신호

## 6. 현재 한계 및 향후 개선 방향

### 한계 1: 저농도 샘플 정확도
- 참가자 47 (MAE 25.5%p) — 정자 농도 낮고 탐지 수 적음
- 근본적 해결을 위해서는 더 많은 저농도 샘플 데이터 필요

### 한계 2: ByteTrack 구조적 한계
- 비운동성 정자 ID 과다 생성 문제 (8.88배)
- 개선 방향: EKF-BoT-SORT 추적기 교체 (구현 복잡도 높음)

### 한계 3: 배율 정보 없음
- 현재 px/frame 단위 → µm/s 변환 불가
- VISEM 데이터셋에 배율 정보 미포함
- 해결 시 WHO 직접 기준 적용 가능

### 한계 4: 형태 분석 미구현
- 현재 운동성 중심 → Phase 3에서 형태 분석 추가 예정
- 필요 데이터셋: HSMA-DS, HuSHeM 등

### 향후 개선 방향

| 단계 | 목표 | 방법 |
|---|---|---|
| Phase 2 | 품질 평가 고도화 | 신뢰도 로직 정교화 |
| Phase 3 | 형태 분석 추가 | 새 형태 데이터셋 도입 |
| Phase 4 | AI-CASA 통합 | 운동성 + 형태 결합 |
